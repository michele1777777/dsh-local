# Agent Note: Smart 审批负责审核，不负责 agent 上下文或沙箱执行

Status: implemented

[English](2026-09-21-smart-approval.md) | 中文

## 问题

Web 与 TUI 需要减少人工权限中断，同时不分裂代理会话行为。在主会话中让任务模型自我批准会改变上下文，并混淆任务完成与授权。现有实验性 Auto 预设还将执行组合改为 Full access，不符合保留普通工作区权限的审核模式要求。

## 决策

[共享 Smart 插件](../../../../packages/interaction/smart-approval/README.zh.md)提供动态可用的当前会话预设，即 `workspace-write` 加 `ask`，以及决定或转交的审批响应器。默认仍为人工模式。审核器独立调用相同提供方与模型，使用有界、标注权限来源的保留输入，无工具，不写主会话。只有低风险允许才可授予精确待执行操作；单次已授权提权可能超出工作区沙箱，但不改变会话整体权限组合。

现有审批服务拥有最终结果与持久审计配对。可选机器审核元数据通过请求局部异步存储附加，保留借用的请求对象身份，并隔离并发请求，即使调用者复用同一对象。审计事件不会暴露为模型上下文。迟到建议不能覆盖取消、核心明确的 `never`、已改变的授权或缺少人工响应器的状态。显式钩子问题和计划或用户问题不会自动回答。

Smart 捕获活动工具注册表拥有的执行身份并与当前步骤日志比较，分别保留人工指令、父代理委派和不可信约束的权限来源。授权不完整、过大或包含非文本内容时转交人工，不截断或捏造上下文。卸载等待审核传输结束，并将已加载的 Smart 会话恢复为普通工作区权限。源码层审批元数据通过[持久化记录](../../../../docs/persistence-changes/2026-09-21-smart-approval-audit.zh.md)确认。

## 考虑过的替代方案

**复用实验性 Auto。** 该预设移除普通沙箱并回答每次工具执行，其拒绝与卸载行为不同。独立身份避免改变已保存选择或悄然授予 Full access。

**在主会话中增加回合。** 这会改变上下文、压缩输入和模型角色；一次性辅助请求避免这些改变，但仍消耗 token 与服务器容量。

**按前缀允许测试与构建。** 仓库脚本可能执行任意代码。确定性检查只拒绝或转交，不凭名字将未知脚本判为安全。

**截断会话以适配上限。** 丢弃限制可能让未授权操作看似合理。完整且有界的保留指令或人工处理能够保留这种不确定性。

## 后果

Manual、Smart 与 Full access 是明确且共享的选择，不是各自独立的 Web/TUI 策略实现。审核器仍具有概率性，可能与主模型犯同样错误；提示和词法检查不是安全边界。压缩后、命令生成任务、非文本指令、shell 脚本或敏感操作可能频繁转交人工。委派子代理保留现有不可提权策略。

本包包含隔离的协议和生命周期测试，以及使用外部提供方夹具的生产服务 Loader 组合测试。隔离测试不能认证真实提供方、原生终端、整个仓库构建或 lint。有限卸载时间要求提供方遵守取消信号，审核延迟、token 和推理服务器争用也与主会话上下文大小相互独立。
