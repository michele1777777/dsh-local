# Agent Note: 基于共享会话控制器的终端原生呈现

Status: implemented

[English](2026-09-18-terminal-native-tui.md) | 中文

## 问题

终端界面需要可读的长对话、安全的交互式审批和易于发现的命令，同时不能再实现一套会话准入、压缩（compaction）、计划或目标逻辑。浏览器式面板和仅追加的输出让终端中的导航和工具细节审阅变得困难。

## 决策

TUI 使用有界的备用屏幕布局，配合缓存的行文档、稳定的条目相对滚动锚点、固定输入框、可搜索命令和逐工具展开。渲染、搜索和折叠都作用于展示状态；提交的文本和附件仍交给既有的 SessionController。预设命令与 Web 使用同一个注册表执行器。提供方的推理（reasoning）内容始终可见，不提供开关。

权限面板只提供既有的单次调用结果。初始选中项为拒绝；选中允许和确认是两个独立操作，因此无需假设终端能够可靠地上报按住按键时的重复事件。计划审阅使用既有的问题 waterfall（瀑布式事件），确认前需要用户显式交互。

该组合包挂载 Web 的只读 session-stats 插件。解码速度和 TTFT 是由其计数器得出的会话平均值。系统不会根据提示词规模和 TTFT 推算预填充速率，因为该延迟并不是独立的预填充耗时。计划、目标激活、当前待办和后台任务都从各自既有的服务或投影读取。

## 考虑过的替代方案

保留 Static 回滚输出可以保持 shell 原生滚动，但若不重新打印内容，就无法支持条目内折叠和稳定的应用内搜索。重建浏览器面板会占用终端空间，却不能改善键盘导航。新增权限模式或由 TUI 自行实现会话逻辑会改变语义，因此未引入。完整的语法解析器和独立的 Git 审阅服务被推迟；高亮是词法级的，差异视图明确只限于工具记录的变更。

## 后果

退出时恢复普通 shell 屏幕；TUI 打开期间，用户在 TUI 内部浏览对话历史。行渲染器和输入路由有确定性测试，编排替身与生产代码明确分离。另提供一套真实的 React/Ink 绘制测试。真实 PTY 行为、安装依赖后的构建以及提供方层面的请求对比，仍需在受支持的运行时中验证。fixture（测试前置数据）预览不能作为这些集成的证据。
